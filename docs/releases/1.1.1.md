# Clipline 1.1.1

Fixes screenshots saved to Desktop failing to appear in Clipline.

Some macOS screenshots lack the `kMDItemIsScreenCapture` extended attribute and instead include a `Screenshot` marker in the image's EXIF UserComment. The Desktop filter in 1.1.0 checked only the extended attribute, so it missed those screenshots. Version 1.1.1 recognizes both markers; ordinary Desktop images are still not automatically added.

If a new image's marker is written slightly later, Clipline briefly retries recognition. It also watches attribute changes for unfinished screenshots. Retries are bounded to avoid continuously polling ordinary images.

The documentation now explains the macOS floating-thumbnail delay: when the native thumbnail is enabled, the screenshot may take several seconds to reach disk, and Clipline must wait for the file. Disable **Show Floating Thumbnail** under **Command + Shift + 5 → Options** to keep your existing save location, or use Clipline's **Handle screenshots** option. Version 1.1.1 does not change this system setting without that option.

Verification: all 47 tests passed, including 5 new Desktop screenshot-recognition tests. The installed release app was checked with the same native macOS screenshot interaction: the older version missed the Desktop screenshot, and the updated version added it successfully. With the native thumbnail disabled, one local observation measured about 0.35 seconds from starting the native screenshot command to adding the item to the shelf; the new-card animation was also captured. This single observation is not a performance guarantee for every machine. The earlier dedicated-folder demo did not cover the Desktop-filter scenario.

Requires macOS 14+ and supports Apple Silicon and Intel. The shared build still uses an ad-hoc signature and is not notarized by Apple.

Installers: `Clipline-1.1.1-universal.dmg` and `Clipline-1.1.1-universal.zip`. Checksums: `SHA256SUMS.txt`.
