# Clipline 1.1.6

Every card now has a visible **Copy** button, replacing the passive “Click to open” footer. Copy text, links, files, or images with one click; a checkmark and **Copied** confirm success. **Retry** appears when copying fails, and unreadable or missing items leave the existing clipboard intact.

- The button is separate from the card's open, drag, discard, and image-hold actions, so copying does not open a document or launch Markup.
- Text copies include the complete stored text, beyond the visible preview. Links retain their URL format, files retain their original file reference, and images retain their bitmap and file URL formats.
- Feedback lasts two seconds and restarts after repeated copies. A new-item preview near its deadline stays visible long enough to show the result.
- Copy and Open are separate accessibility actions, with meaningful labels and hover help. Card-body opening and the right-click menu remain available.

**Validation:** all **139 automated tests passed**, including hosted SwiftUI/AppKit regression tests for live success and retry labels. Native verification using the same application sources exercised all four Copy buttons, full 1,298-character text, a held image Copy button, failure without replacing the clipboard, successful retry, and card-body opening. The fixture used synthetic content and an isolated pasteboard. Universal arm64/x86_64 builds, strict signature verification, DMG/ZIP contents, and SHA-256 checksums passed validation.

Requires macOS 14+. The shared build uses an ad-hoc signature and is not notarized by Apple. An update may request screenshot-folder or Accessibility access again.

Installers: `Clipline-1.1.6-universal.dmg` and `Clipline-1.1.6-universal.zip`. Checksums: `SHA256SUMS.txt`.
